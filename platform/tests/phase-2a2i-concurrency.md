# Phase 2A.2-I deterministic concurrency

The disposable runner uses two distinct WP-CLI/MySQL sessions, real application hooks, explicit convergence gates, and an explicit release file. In mode `a`, both different-Family workers must first report their independently locked source IDs and Family IDs at `dzn_phase_2a2i_source_lineage_locked`; the runner verifies their shared Student/Course tuple, releases worker 1 to hold the concrete identity root, and only then releases worker 2 toward that same root. Mode `b` proves same-source serialization; `u1` and `u2` prove unrelated identity roots can progress before release; `p1` and `p2` prove both privacy/conversion orderings through the Booking Request lock. Timing is not the success oracle: every run verifies gates, worker outcomes, and authoritative database state after both transactions finish.
